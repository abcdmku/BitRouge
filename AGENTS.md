# BitRouge Agent Guide

## Project Shape

- `src/game`: pure simulation, content definitions, selectors, save schema, and tests. No imports from `react`, `phaser`, or browser globals (`window`, `document`, `localStorage`). A purity test enforces this.
- `src/render`: Phaser display only. Consumes `RenderSnapshot`, emits `RenderCommand`. Zero game logic; no state that the sim does not already own.
- `src/ui`: React components, hooks, CSS, and browser interaction. Owns the keyboard.
- `src/platform`: persistence, offline-advance worker, and platform adapters.
- `scripts/`: asset pipeline (`build-sprites`, `contact-sheet`, `fetch-packs`) run with `tsx`.
- `assets-src/`: art sources (`palette.json`, `STYLE.md`, `*.sprite.txt`). Hand-edited.
- `public/assets/gen/`: generated by `npm run build:sprites`. Do not hand-edit; regenerate.
- `public/assets/packs/`: third-party CC0 packs fetched by `npm run fetch:packs`, with their licenses.
- `docs/`: `game-spec.md` and non-runtime notes.

Game rules belong in `src/game`. React and Phaser call game functions; they do not own progression, unlocks, rewards, timers, or balancing rules.

All simulation timing is hardware-derived: work volumes advance through component rates (`clockHz`, throughput). Do not add wall-clock timers where hardware can own the duration. Fixed clocks are only deadlines or physical latencies, and must be named as such.

`advanceGame(state, elapsedMs)` must be delta-invariant: `advance(200) ≡ advance(100)∘advance(100)`, including RNG draws.

## Pre-Live Design Policy

BitRouge is pre-live. Breaking save schema, UI, and mechanic changes are allowed when they move the prototype toward `docs/game-spec.md`. Keep the spec aligned with those changes and prefer reset notes over preserving obsolete behavior.

## Coding Standards

- Strict TypeScript. `npm run typecheck` must pass.
- Pure functions for simulation and selectors; immutable updates for game state.
- Currencies are `Amount` (exact decimal strings), never floats.
- All randomness goes through `src/game/rng.ts` and threads state explicitly.
- Keep files focused and under a few hundred lines; split by domain.
- Model state with explicit types instead of loose objects.
- Save serializable game state, not UI or Phaser objects.
- Add tests next to the code (`*.test.ts`). `npm run verify` must stay green.

## UI Standards

- The first screen is playable.
- Concise copy: labels, values, unlock reasons, warnings.
- Readable on desktop and mobile; respect safe-area insets; `image-rendering: pixelated`.
- Do not move controls in response to runtime status changes. Reserve stable geometry and update in place.

## Subagent Ownership

- Lead/integrator owns root docs, configs, dependency choices, and final consistency.
- Simulation agent owns `src/game/**`.
- Renderer agent owns `src/render/**`.
- UI agent owns `src/ui/**`.
- Platform agent owns `src/platform/**`.
- Pipeline agent owns `scripts/**` and `assets-src/{palette.json,STYLE.md}`.
- Art agents own only their assigned `assets-src/sprites/*.sprite.txt` files.

Agents are not alone in this repository. Do not revert edits made by others. Keep changes scoped to your owned area and adapt to nearby work.
